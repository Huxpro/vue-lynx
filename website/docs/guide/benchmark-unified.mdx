# Unified Benchmark Matrix

One place to **look at** every architecture on the same host and ladder —
IFR styles, VDOM vs Vapor, and React vs Vue — without mixing metric scales.

**How to read storms:** **Select = point update** (selection / a few classes
per tick). **Update = batch update** (many rows touched each pass). Don’t
compare those two curves as if they were the same workload.

## How to read it

1. **Conclusions** — digestible product guidance; numbers are for checking.
2. **First screen** — the interaction-free half: `startup` (attach → first
   content, empty app) and the `mount-create` ladder (the app is *built*
   with N rows already in the table, 1k→30k). Two curves: absolute ms, and
   the same data normalized to the `vdom` baseline so host drift cancels.
   This is where the third framework family,
   [Octane](https://github.com/octanejs/octane), appears — see below.
3. **Storm table / charts** — point (select) vs batch (update) latency.
   Octane is a column there too, rendered as a hoverable `N/A`.
4. **FCP table / charts** — content-probe first-frame ladder (separate instrument!).
5. **Optimization-flag matrix** — every legal combination in V4 notation
   `render [+b[:d|c|e]] [+ifr[:c|e]]` (baseline = per-node; `+b` = block
   templates; `+b:e` = engine staging, N/A on web and omitted; `+ifr:e` =
   engine-painted first frame only), measured for create/update with
   per-flag marginal factor deltas and a full flag legend on the page.
   Formalization: [`GRAPH-ENG-REPORT.md`](https://github.com/Huxpro/vue-lynx/blob/vapor/packages/ifr-bench/GRAPH-ENG-REPORT.md) §1.3c.

## Octane (third framework family)

[octanejs/octane](https://github.com/octanejs/octane) ships its own private
Lynx renderer (`@octanejs/lynx`). Its bundles **do run on Lynx for Web** —
same `@lynx-js/web-core` runtime as the Vue and React cells — but its native
event loop is not wired: the host driver registers a string token with
`__AddEvent`, and the only decoder is called exclusively from octane's own
tests. Taps therefore reach nothing, so **every click-driven metric is
unmeasurable for Octane** and it appears in the *First screen* section only.

Octane always paints the first screen on the main thread with no opt-out, so
the fair Vue comparators are the `+ifr` rows. On an *empty* first screen it
lands inside that band (a tie — the leaders are within a few ms and the
sample ranges overlap). Once the first screen has content it is a flat
**1.6–1.8× the `vdom` baseline across the entire 1k→30k ladder** — a constant
per-node factor, not a penalty that only shows up at one size. Its per-node
object command protocol has no template/tree registration to amortize, where
the Vue cells collapse repeated structure into `INSTANTIATE_TEMPLATE` /
`REGISTER_TREE`+`CLONE_TREE`.

Method, caveats and the full reading:
[`packages/benchmark/OCTANE.md`](https://github.com/Huxpro/vue-lynx/blob/vapor/packages/benchmark/OCTANE.md).

## Environment rules

- **lynx-web** — primary product scale (this report).
- **bare-dom** / **node-jitless** — different instruments; never ratio across them.
